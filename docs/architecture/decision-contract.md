# 决策合同：规则、证据与输出

这份合同解决的不是“如何让 Agent 更会说”，而是“它在什么条件下才可以说出一个判断”。当前工作台会保存规则判断和运行快照，但**不会连接 Amazon**、不会调用 MCP，也不会把卖家填写的数字伪装成类目事实。

## 两个可审查文件

- [`contracts/decision-rules.yaml`](../../contracts/decision-rules.yaml)：定义 Gate、所需字段、可接受的证据状态，以及资料缺失时禁止做出的结论。
- [`contracts/output-schema.json`](../../contracts/output-schema.json)：定义任何未来策略输出的固定结构。

规则目前覆盖：

- 总预算可行性；
- SB 是否具备进入规则判断的资料；
- SD 与老品导流是否具备进入规则判断的资料；
- 是否可以展示按 Campaign 拆分的预算草案。

## 证据不是一个布尔值

每项证据都必须带 `value`、`status`、`source` 和 `captured_at`：

- `confirmed`：卖家确认，不能当作外部验证；
- `verified`：授权外部来源已验证；
- `external_evidence`：外部来源提供了材料，但仍需要业务人员解释或确认。

授权外部来源的名称会被记录，例如 `amazon_ads_mcp`、`seller_spreadsheet`、`catalog_mcp` 或 `inventory_mcp`。未来新增连接器时，先更新证据转换层和测试；不要直接修改策略文案来绕过来源记录。

## Gate 的适用范围

未选择的广告类型不执行 Gate，状态记录为 `not_applicable`。这不是缺少资料。

卖家已填写不等于外部已验证。卖家填写的品牌、ASIN、库存或毛利可以记录为 `confirmed`；账户资格、品牌注册资格和广告展示资格只有授权外部来源才能记录为 `verified`。

## 输出边界

任何后续 Agent 结论都必须包含：主张、对应证据、规则 ID 与版本、卖家假设、缺失/冲突字段、下一步以及资源使用情况。资料不完整时，状态必须是 `information_required`，只返回缺口与下一步，**不生成策略结论**。

例如：没有关键词与商品定向的外部证据时，可以显示总预算的公式可行性，但不得将每个 Campaign 的金额或分配比例呈现为真实或策略 Campaign 建议。当前本地工作台仍可展示 `30% / 45% / 25%` 固定演示分配，仅用于证明 UI 流程；它不是市场证据，也不可直接执行。

## 变更方式

规则或输出字段的变更应当：

1. 提高对应规则或合同版本；
2. 先新增失败测试，再修改实现；
3. 保留旧运行快照中的原版本，不回写历史结论；
4. 在 UI 显示本次结论引用的规则与证据来源。
